# TradingCopilot

TradingCopilot 是 TradingAgent 仓库内独立的 A 股人工决策辅助产品域。它服务个人主观实盘，把用户申报资金/持仓、关注股、TradingAgent 已验证证据和人工判断组织成可审计的行动卡。

## 与量化核心的区别

| 维度 | TradingAgent Quant Core | TradingCopilot |
|---|---|---|
| 决策主体 | 冻结策略、组合与强制风控 | Nicholas |
| 账户 | 市场隔离的量化模拟/未来量化实盘账户 | 用户申报的个人主观账户 |
| 输出 | StrategyOrderIntent / simulation receipt | UserActionCard / UserDecisionIntent |
| 执行 | 当前 sim-only；未来经合规与显式授权接市场专属 adapter | 当前仅记录计划、观察或不交易 |
| 学习 | 市场规律、费用后正期望、组合与执行 | 个人决策纪律、覆盖缺口和计划偏差 |

## 共享底座与独立能力

原则固定为：**计算与证据尽量复用，账户与决策 authority 永远隔离**。机器可读责任表见
[`contracts/shared_capability_boundary.v1.json`](contracts/shared_capability_boundary.v1.json)。

| 能力层 | 可共享的底层 | Quant Core 专属 | TradingCopilot 专属 |
|---|---|---|---|
| 数据 | TradingDatas 行情、OHLCV、证券主数据、交易日历、公司行动、财务数据 | 数据合格后进入候选/策略样本的资格判断 | 关注股与申报持仓对应的数据展示、缺失状态 |
| 市场规则 | T+1、100股整手、涨跌停、费用和滑点口径 | 订单合法性、资本预约、硬风险放行 | 人工交易提醒、计划数量和可卖数量检查 |
| 研究特征 | PIT observation、技术/横截面特征、质量与新鲜度回执 | 候选排名、Champion、组合优化和策略仓位 | 支持/反对证据、触发条件与失效条件的解释展示 |
| 事件 | 按股票绑定的公告、新闻、舆情、来源和发布时间 | 是否进入策略特征及其权重 | 个股事件时间线、人工关注提醒 |
| 预测模型 | 基线、Kronos Challenger、模型清单、OOS、校准、区间覆盖率和成本后指标 | 模型竞赛、策略采用、SampleJournal、KPI和人工晋级 | 读取已发布投影，结合个人账户形成决策辅助；无权训练、晋级或改变模型 |
| 风险语境 | 市场状态、波动、流动性、板块与风险警示的只读证据 | 组合风险预算、下单资格、暂停和风险收紧 | 个人持仓集中度提醒、人工减仓/等待条件 |
| 账户与执行 | 不共享可写状态 | 量化资本账本、预约、outbox、BrokerAdapter、fill和reconcile | 用户申报资金/持仓、关注列表、人工计划/观察/跳过 |
| 复盘 | 可共享统一的时间、费用和绩效计算定义 | 量化交易样本、策略收益、模型标签和晋级统计 | 主观交易日志、计划偏差和个人纪律复盘；不得进入量化学习 |

正确的数据流是：共享研究/模型平面生成一次正式只读投影，Quant Core 用它做系统化候选与组合判断，TradingCopilot 用同一投影叠加个人申报账户和人工约束。Copilot 不复制正式预测引擎；Quant Core 也不读取 Copilot 的个人资金、持仓或人工计划。

Kronos 因而属于共享 learning/research 底座，不是 Copilot 私有模型。它先以
`kronos_challenger` 在同一冻结样本上与基线比较；通过OOS、校准、覆盖率和成本门禁后，
只发布版本化预测证据。Quant Core 是否采用、Copilot 是否展示，是两个独立消费决定；
任何一侧都不能反向修改模型或替另一侧取得资金/订单 authority。

分钟频率不是量化优势本身。量化系统的潜在优势来自全量一致扫描、可重复规则、多因子联合、组合级风险、低情绪干扰、执行纪律、成本控制和持续样本外迭代。只有在真实PIT数据、完整覆盖、费用/滑点和独立样本外结果通过后，这些工程能力才能被称为已证明的策略优势。

当前 TradingAgent 已建立数据证据、模拟资本、风险、执行原子性、样本和复盘合同，但尚未证明全A股实时覆盖、稳定alpha或真实量化执行。因此 TradingCopilot 必须逐标的显示分析来源：

- `tradingagent_observation`：来自本轮可验证 TA 只读证据；
- `demo_fixture`：仅用于网页交互和视觉验收；
- `analysis_unavailable`：已关注，但TA尚无可用分析。

## V1 功能

- 手工维护申报资金、可用现金和持仓；
- 新增、搜索和切换关注股票；
- 展示支持买入、反对买入、最终判断、建议强度和买入条件；
- 记录“加入计划 / 继续观察 / 暂不交易”；
- 显示数据新鲜度、分析来源、T+1和100股整手提醒；
- 所有状态留在独立Copilot namespace，不写量化账户和订单链。

## V2 个股详情工作台

个股页参考专业金融终端的连续阅读方式，形成“行情 → 预测情景 → 事件解释 → 多空证据 → 人工决定”的单页路径：

- `1D / 5D / 1M / 6M / YTD / 1Y` 多周期价格和成交量图；
- 历史价格使用实线，未来研究情景使用虚线中位线与宽/窄研究包络；未校准包络不使用概率标签；
- 预测只允许标记为 `shadow_uncalibrated` 或未来经过样本外验证的正式模式；当前情景权重不是上涨概率、胜率、目标价或收益承诺；
- 公告、新闻和舆情必须按 `symbol` 显式关联，并保留类型、来源、发布时间、摘要、情绪标签和来源链接状态；
- 概述、财务数据、收益、持有者、预测、历史数据和分析页签都必须有真实状态。合同未交付时展示不可用，不生成替代内容；
- 演示行情、事件和预测继续统一标记 `demo_fixture`，只服务界面和交互验收。

## V3 预测交付边界

V3 把“预测功能存在”和“预测可用于人工决策”拆成机器可验证的状态，不允许用页面免责声明替代功能门禁：

- 所有预测必须使用冻结期限 `m30 / m60 / close / 1d / 3d / 5d` 之一；页面同时显示当前期限，禁止把分钟与未来五日合成一个结论；
- `shadow_uncalibrated` 只能显示定性方向、研究中位线和“窄幅/宽幅研究包络”，默认关闭；禁止显示上涨概率、胜率、50%/80% 区间或其它置信度措辞；
- 演示研究曲线由最近最多20个点的确定性线性基线生成，斜率逐步上限为末值的1.5%，包络由残差中位绝对尺度派生；相同输入必须可重放。它只证明基线计算和界面门禁，不证明市场预测力；
- 只有 `assessForecastReadiness()` 的十一项门禁全部通过，状态才可成为 `decision_support_ready`，并允许概率和覆盖率标签。门禁包括正式观察、明确期限、模型清单、PIT/修订链、冻结OOS、独立校准证明、至少40个有效独立样本、区间覆盖率、费用/滑点口径、同一PIT基线对照和扣除成本后的正净效用；正式投影中的清单、PIT、OOS、校准、覆盖率、成本和基线证据都必须绑定可验证ID与SHA-256；
- `kronos_challenger` 与最后值、线性/岭回归基线使用完全相同的门禁。模型名称不能放行概率；Kronos 只有在同一冻结样本、期限、成本与指标上证明稳定增量后，才可进入人工评审；
- 前端通过只读 `GET /api/trading-copilot/stock-intelligence?symbol=<A股代码>` 读取正式个股投影。默认文件入口为 `runtime/tradingcopilot/stock-intelligence/<symbol>.json`；只接受 `tradingagent_observation`、股票代码绑定、事件逐项绑定和预测readiness自洽的投影，失败返回不可用且不回退provider或生成曲线。

本阶段的必须交付是：门禁合同、正式投影读侧、误导性概率停显、期限显示、Kronos Challenger 边界和自动化负例全部可运行。Kronos 权重下载、常驻推理和模型合并不在该交付边界内；它们属于M2模型竞赛，开始条件仍是A股至少20个交易日模拟且历史PIT可用。提前安装模型不能替代这些输入条件。

当前 TradingAgent 的普通信号快照只能形成 `tradingagent_observation` 分析卡，不能据此推导完整 OHLCV、公告、新闻或概率预测。正式个股行情与事件数据必须由独立 observation worker 从 TradingDatas 固定 `catalog/query` 数据面验收后形成本地只读投影；`front/` 不直连 provider、不持有 TradingDatas credential，也不把历史 production evidence 当作当前可消费数据。

## V4 个股终端展示边界

个股首屏按专业金融终端的阅读层级收敛为“左侧行情与指标、右侧公司资料与解释卡、下方事件和关键问题”。本阶段的必须交付包括：

- 公司代码、上市日期、行业、地区、交易所和简介只读取当前个股投影；缺失时显示不可用；
- “Copilot 证据共识”只统计当前 `CopilotAnalysis` 的支持/反对证据并显示独立证据强度语义，不把普通信号 `confidence` 映射成评分，也不冒充上涨概率、胜率、分析师覆盖或市场一致预期；
- “舆论与事件温度”只聚合当前股票已绑定的公告、新闻、舆情事件方向和最近时间，不把热度转换为价格概率；
- “显著价格变化”把当前价格相对前收与关联事件并列呈现，并明确事件解释不能单独形成买入理由；
- 关注列表使用独立管理工作区，保持新增、搜索和切换能力，同时不给主行情图永久挤占一列；
- 本阶段只验收桌面端；页签、多周期与预测停显门禁必须通过真实浏览器验收。移动端不作为当前交付边界。

## V5 个人状态与导航语义

个人状态必须先于展示样例，且完整组合与当前股票关系不能混为一谈：

- 普通 `/?product=copilot` 只读取个人状态账本；空账本显示真实空状态，不因开发模式自动注入演示关注或持仓；
- 演示只通过 `?product=copilot&demo=1` 或 `VITE_TRADING_COPILOT_DEMO_PREVIEW=1` 显式开启，始终标记为独立演示样例，页面修改不写服务端或本机草稿；
- “关注列表”“资金与持仓”“决策记录”是独立工作区。关注不等于持仓；全部持仓必须在组合页可见，个股右栏只显示当前股票的申报关系；
- 新增申报持仓会自动加入关注；移除持仓保留关注；持仓未移除前不能从关注列表删除，避免持仓股票失去持续观察；
- 申报总资金、可用现金和持仓成本分别展示。缺少实时市值时，不用“总资金 − 现金 − 成本”伪造资产核对差额；券商总资产仍标记为待人工确认；
- 移动端保留四个主工作区导航，列表改为卡片布局，不能因隐藏侧栏而失去关注或持仓入口。

上述能力仍属于 Copilot 展示和个人决策层。它没有新增 Quant Core 写入口，也没有改变 `shared_capability_boundary.v1.json` 中行情/事件/模型只读共享、资本/订单/样本/晋级隔离的责任划分。

## V7 证据与人工决策完整性

- 正式个股投影必须同时提供 `<symbol>.json` 与 `<symbol>.receipt.json`。服务端校验股票代码、投影哈希、生成/截止时间、验证器和来源回执后才向前端暴露 `formal_projection`；缺失、错配或被篡改时直接不可用。
- 个人状态服务使用 `ETag/If-Match` 做并发写入控制，使用进程锁避免同进程并发覆盖，并在每次读写前验证状态哈希、事件序号、前序哈希和事件哈希链。浏览器本地回退只能标记为未同步草稿，不能覆盖更晚的服务端版本。
- 人工决定必须分别记录理由、触发条件、失效条件和可选风险上限；复盘另行记录状态、实际动作、备注与时间。两者都是 TradingCopilot 人工意图账本，不是委托或成交回执。
- 公告、新闻和舆论事件逐项展示来源置信、发布时间、采集时间、新颖性、影响方向/期限与正式回执状态；热度和情绪不能单独放行交易。
- A股市场、T+1、整手、涨跌停、ST、可交易状态和复权口径在个股页显式展示；财务数据缺失时对应页签失败关闭，不能用行情指标伪装财务报表。

## V8 正式投影、组合复核与 Challenger 评估

- `Ashare.trading_copilot_observation_worker` 复用现有分钟 Evidence Gate，行情仍只经 TradingDatas `GET /v1/catalog` 与 `POST /v1/query` 进入；证券主数据只能来自五项 committed current-observation bundle 或另一个带 TradingDatas 回执的显式输入。休市日的 `historical_display` 只展示带当前查询回执的旧行情并标记 `stale`，不取得 historical-PIT 训练、延迟模拟或执行资格。前端不接 token，也不直连数据源。
- 批量发布先验证完整批次，再原子写入每只股票的 projection/receipt；行情、证券主数据和每条事件的全部来源回执都进入 detached receipt。批内任一代码、时间、OHLC、来源、事件链接或双向证据不合格时，本批在写第一只股票前整体失败。
- 公告、新闻和舆论必须包含代码绑定、来源类别、来源置信、发布/采集时间、URL、内容哈希和来源回执。没有正式分类回执时，事件只发布 `neutral/uncertain`，不由摘要文字猜测情绪或影响；没有可验证 URL 的事件不展示。
- 组合页按用户申报成本分别复核资金算术、单股集中、已验证行业重叠、T+1可卖数量与人工计划风险上限。缺失行业不会被合并成一个虚构行业，最大风险也不会被当作计划投入或现金预约。
- `Ashare.trading_copilot_forecast_evaluation` 在相同冻结样本、相同期限和相同成本口径上比较最后值、线性/岭基线与可选 Kronos。它校验决策时间早于标签时间、模型样本集合一致，并输出 MAE、方向准确率、扣成本方向效用、区间覆盖与有效独立样本数。
- Kronos 不是必需依赖。只有有效独立样本不少于40、MAE至少比线性基线改善5%、方向准确率不低于基线且扣成本效用为正，才可进入 `eligible_for_shadow_comparison`；这仍不是校准通过、模型晋级或交易权限。正式概率线还必须继续通过前端十一项 readiness 门禁。

本阶段桌面端是唯一展示验收面。正式批量投影工作器、组合人工复核和 Challenger 评估框架属于仓库能力；某一运行批次覆盖多少股票、事件数据集是否完整、预测是否可展示，必须以该批次回执为准，不能从代码容量推断。

## 当前停止线

- 不把演示分析称为实时分析；
- 不把用户申报持仓称为券商确认；
- 不提供发送订单或确认成交按钮；
- 不因少量用户而省略身份、来源、时间和权限标签；
- 不把TradingCopilot个人交易结果用于量化模型自动晋级。
