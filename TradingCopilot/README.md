# TradingCopilot

TradingCopilot 是 TradingAgent 仓库内独立的 A 股人工决策辅助产品域。它服务个人主观实盘，把用户申报资金/持仓、关注股、TradingAgent 已验证证据和人工判断组织成可审计的行动卡。

## 与量化核心的区别

| 维度 | TradingAgent Quant Core | TradingCopilot |
|---|---|---|
| 决策主体 | 冻结策略、组合与强制风控 | Nicholas |
| 账户 | 市场隔离的量化模拟/未来量化实盘账户 | 用户申报的个人主观账户 |
| 输出 | StrategyOrderIntent / simulation receipt | UserActionCard / UserDecisionIntent |
| 执行 | 当前 sim-only；未来经合规与显式授权接市场专属 adapter | 当前仅记录计划、观察或不交易 |
| 学习 | 市场规律、费用后正期望、组合与执行 | 个人决策纪律、覆盖缺口和计划偏差 |

分钟频率不是量化优势本身。量化系统的潜在优势来自全量一致扫描、可重复规则、多因子联合、组合级风险、低情绪干扰、执行纪律、成本控制和持续样本外迭代。只有在真实PIT数据、完整覆盖、费用/滑点和独立样本外结果通过后，这些工程能力才能被称为已证明的策略优势。

当前 TradingAgent 已建立数据证据、模拟资本、风险、执行原子性、样本和复盘合同，但尚未证明全A股实时覆盖、稳定alpha或真实量化执行。因此 TradingCopilot 必须逐标的显示分析来源：

- `tradingagent_observation`：来自本轮可验证 TA 只读证据；
- `demo_fixture`：仅用于网页交互和视觉验收；
- `analysis_unavailable`：已关注，但TA尚无可用分析。

## V1 功能

- 手工维护申报资金、可用现金和持仓；
- 新增、搜索和切换关注股票；
- 展示支持买入、反对买入、最终判断、建议强度和买入条件；
- 记录“加入计划 / 继续观察 / 暂不交易”；
- 显示数据新鲜度、分析来源、T+1和100股整手提醒；
- 所有状态留在独立Copilot namespace，不写量化账户和订单链。

## V2 个股详情工作台

个股页参考专业金融终端的连续阅读方式，形成“行情 → 预测情景 → 事件解释 → 多空证据 → 人工决定”的单页路径：

- `1D / 5D / 1M / 6M / YTD / 1Y` 多周期价格和成交量图；
- 历史价格使用实线，未来研究情景使用虚线中位线与宽/窄研究包络；未校准包络不使用概率标签；
- 预测只允许标记为 `shadow_uncalibrated` 或未来经过样本外验证的正式模式；当前情景权重不是上涨概率、胜率、目标价或收益承诺；
- 公告、新闻和舆情必须按 `symbol` 显式关联，并保留类型、来源、发布时间、摘要、情绪标签和来源链接状态；
- 概述、财务数据、收益、持有者、预测、历史数据和分析页签都必须有真实状态。合同未交付时展示不可用，不生成替代内容；
- 演示行情、事件和预测继续统一标记 `demo_fixture`，只服务界面和交互验收。

## V3 预测交付边界

V3 把“预测功能存在”和“预测可用于人工决策”拆成机器可验证的状态，不允许用页面免责声明替代功能门禁：

- 所有预测必须使用冻结期限 `m30 / m60 / close / 1d / 3d / 5d` 之一；页面同时显示当前期限，禁止把分钟与未来五日合成一个结论；
- `shadow_uncalibrated` 只能显示定性方向、研究中位线和“窄幅/宽幅研究包络”，默认关闭；禁止显示上涨概率、胜率、50%/80% 区间或其它置信度措辞；
- 演示研究曲线由最近最多20个点的确定性线性基线生成，斜率逐步上限为末值的1.5%，包络由残差中位绝对尺度派生；相同输入必须可重放。它只证明基线计算和界面门禁，不证明市场预测力；
- 只有 `assessForecastReadiness()` 的九项门禁全部通过，状态才可成为 `decision_support_ready`，并允许概率和覆盖率标签。门禁包括正式观察、明确期限、模型清单、PIT/修订链、冻结OOS、独立校准证明、至少40个有效独立样本、区间覆盖率和费用/滑点口径；
- `kronos_challenger` 与最后值、线性/岭回归基线使用完全相同的门禁。模型名称不能放行概率；Kronos 只有在同一冻结样本、期限、成本与指标上证明稳定增量后，才可进入人工评审；
- 前端通过只读 `GET /api/trading-copilot/stock-intelligence?symbol=<A股代码>` 读取正式个股投影。默认文件入口为 `runtime/tradingcopilot/stock-intelligence/<symbol>.json`；只接受 `tradingagent_observation`、股票代码绑定、事件逐项绑定和预测readiness自洽的投影，失败返回不可用且不回退provider或生成曲线。

本阶段的必须交付是：门禁合同、正式投影读侧、误导性概率停显、期限显示、Kronos Challenger 边界和自动化负例全部可运行。Kronos 权重下载、常驻推理和模型合并不在该交付边界内；它们属于M2模型竞赛，开始条件仍是A股至少20个交易日模拟且历史PIT可用。提前安装模型不能替代这些输入条件。

当前 TradingAgent 的普通信号快照只能形成 `tradingagent_observation` 分析卡，不能据此推导完整 OHLCV、公告、新闻或概率预测。正式个股行情与事件数据必须由独立 observation worker 从 TradingDatas 固定 `catalog/query` 数据面验收后形成本地只读投影；`front/` 不直连 provider、不持有 TradingDatas credential，也不把历史 production evidence 当作当前可消费数据。

## 当前停止线

- 不把演示分析称为实时分析；
- 不把用户申报持仓称为券商确认；
- 不提供发送订单或确认成交按钮；
- 不因少量用户而省略身份、来源、时间和权限标签；
- 不把TradingCopilot个人交易结果用于量化模型自动晋级。
